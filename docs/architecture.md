# Architecture

`Core` defines profiles, file snapshots, duplicate groups, path protection and deterministic keeper planning. It has no WPF or persistence dependency. `Infrastructure` handles Win32 identity, locked read streams, SHA-256, byte comparison, incremental scanning, SQLite, cleanup journaling and streaming exports. `App` composes these through explicit Microsoft DI registration and binds the WPF workflow through a view model and commands. Async command boundaries display failures and treat cancellation as a normal outcome.

The [scanning guide](scanning-and-comparison.md) is authoritative for enumeration, sampling, hashing, byte verification and stability decisions. The [architecture and logic diagrams](diagrams.md) make boundaries and failure paths reviewable; [ADRs](decisions/README.md) record why conservative local verification and SQLite were chosen.

One file is hashed at a time. Verification holds two handles; cleanup copy verification holds at most three. This conservative resource profile avoids unbounded task creation, read queues and drive listings. SQLite handles metadata beyond RAM capacity. The result grid virtualizes and loads bounded pages; exports iterate database rows. The UI receives progress at most roughly seven times per second. Expensive work runs via Task.Run and cancellable asynchronous stream operations.

SQLite stores scans, physical snapshots, issues and operation journal entries. [Schema](schema.md) documents authoritative structure, indexes, logical relationships, per-connection durability and transactional numbered migrations. An exclusive data-directory file lease precedes database initialization/recovery to exclude concurrent app sessions. Startup converts in-flight work to interrupted state. [Safety and recovery](safety-and-recovery.md) defines cleanup validation and recovery limits; no batch or filesystem/database combination is atomic.

The view model coordinates settings and pages through an injectable dialog boundary. Async commands retain the busy state through journal/history refresh; confirmations precede mutation. The shared resource dictionary supports native-window dispatcher tests. The view model coordinates dialogs; native operations remain outside it. Tests combine domain and local NTFS fixtures in one project. Shared Version.props supplies version metadata. Documentation tooling is a separate development dependency: Python derives structural references, pinned Node tools lint Markdown/render Mermaid, and a read-only PR gate evaluates declared impact. It does not execute the app, change source, approve or publish. See [testing](testing.md) and [limitations](known-limitations.md).
